# ADR-0002 — Browser-local Image Processing

## Status

Accepted。2026-10-30 整理从早期原生实验、C1/C2 到 D2 已确立的选择，不将该日伪装为原始决策日期。

## Context

图片可能含私密内容和来源元数据；首款工具需要真实转换、批处理和可下载输出，不能只根据扩展名或浏览器声明判断成功。浏览器原生能力足以处理部分格式，而 AVIF 等重型编码有不同性能、内存和许可成本。通用工具平台还需支持不同工作区，不能因此耦合某个图片编码器。

## Decision

- 用户文件在浏览器本地处理，不上传或持久保存；静态页面与编码资源由站点正常分发。
- 原生编解码优先，能力检测验证真实产物；必须借助重型编码时按实际任务加载独立资源。当前 AVIF 为固定单线程 jSquash Worker/WASM，独立预算、取消和回收。
- 正确性与隐私优先：有界检查输入、拒绝动画/不可靠变体、验证实际格式/方向/尺寸/完整解码；默认清理常见来源信息，作者版权只开放已验证白名单组合。
- 优先无损清理同格式压缩载荷，不为了去元数据无条件再次有损编码；不能可靠处理时明确失败，不偷换格式或绕过验证。
- 任务、版本、资源和交付归工具；Workbench/UI 只负责可复用布局与受控交互，不建立跨媒体总引擎或第二任务系统。

## Alternatives Considered

- **服务端上传转换**：可统一计算环境，但改变隐私边界并需要当前没有的后端、存储和运维。
- **所有格式统一大型 WASM 框架**：覆盖面更广，但首屏/内存/依赖与许可成本过高，并强迫已足够的原生路径一起迁移。
- **完全原生或仅信 toBlob**：不能保证目标编码、AVIF 参数和透明度语义，可能实际回退到其他格式。
- **Quick 始终原字节直通 / 默认全量重编码**：前者会保留 GPS 等信息，后者造成不必要画质与文件大小变化；采用受限清理加显式拒绝/主动重编码。

## Consequences

用户文件留在本地，普通格式不下载 AVIF 引擎；真实验证与版本资格统一保护预览、下载和 ZIP。代价是浏览器/设备差异、有界解析器与资源回收维护、特殊变体明确不支持，以及旧二进制的安全维护责任。桌面证据不能推出移动真机安全，未知平台按 L3 跟进，不能承诺完整元数据或专业色彩保全。
